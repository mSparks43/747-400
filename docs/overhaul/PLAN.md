## 0. 方針

- **順番**：依存関係の順に進める。電源・空地判定・警報の枠組み・油圧・空圧などの土台を先にし、自動操縦・推力管理・FMC を最後にする。
- **1 項目ごとの流れ**：TESTING.md §5 のとおり。
  1. 方針を示す。
  2. 実装する。
  3. 構文チェック。
  4. 回帰試験（LuaJIT）。
  5. X-Plane での試験（飛行試験キット、Web API）と Log.txt の確認。
  6. 報告。
  7. コミット。
- **作り直し**：GAP_ANALYSIS.md の推奨どおり、ほとんどの系統はモジュールを作り直す。INTERFACES.tsv の名前と意味（パネルの表示条件の名前を含む）は保つ。
  - 作り直す系統の表示灯・EICAS メッセージ・quick start の設定は、その系統の作り直しと一緒に移す。
- **基準の機体**：FCOM の機体番号 109（PW4056 の旅客機）。GE は 570 の値を使う。
  - 貨物機（405・570）の違いは、機体設定の `freighter` に合わせる。
  - RR には資料が無いので、今の動きのまま残す。
- **資料に無いこと**：推測で作らない。やむを得ない部分は、コードと PROGRESS.md に「推定」と書く。
- **acf**：
  - 純正 acf は変えない。
  - カスタム acf のシステム・エンジン・空力の設定は、バックアップを取り、変更前後の値を報告したうえで変える。
  - 見た目に関わる変更（パネル計器を含む）と `.snd` の変更は、§3 のとおり 2026-10-23 に承認された。
- **XLua・C++**：それを使うのが最善と判断できる場合に採用する（利用者の許可あり）。今のところ予定は無い。

## 2. 進め方の補足

- 段階 1 の中の順番は、1-1 → 1-2 → 1-3 → 1-4・1-5 とする。1-4 と 1-5 は、デマンドポンプ（ADP）とダクト圧の取り決めを先に決めれば並行できる。
- 各系統の作り直しでは、系統の公開 dataref を先に出し、旧い出力（INTERFACES.tsv の名前）を新しいモデルから埋める。消費側の乗り換えは、同じ項目の中で終わらせる。
- 区切り（段階の終わり）ごとに、純正 acf で起動・電源投入・エンジン始動の基準シナリオを回す。
